DATA FLOW: User Query → Response

1. User types message in browser (frontend/index.html)
2. JavaScript validates (app.js): non-empty, ≤2000 chars
3. WebSocket sends: {type: "message", session_id, content}
4. Backend receives (websocket_handler.py)
5. Validates message format, session ID
6. Calls conversation_manager.get_response(session_id, content)
7. Manager retrieves session history (if exists) or creates new
8. prompt_builder constructs messages list:
   - System prompt (gadgetmart_facts.txt)
   - Session summary (if context > 10 turns)
   - Last 10 turns of history
   - Current user message
9. ollama_client.chat_stream(messages) → Ollama HTTP request
10. Ollama loads Qwen2.5 model, generates tokens (streaming)
11. Backend yields chunks: {type: "chunk", content: "..."}
12. Frontend appends each chunk to message bubble in real-time
13. On completion, backend sends: {type: "done", turn_id, total_tokens}
14. Frontend finalizes message (adds copy button, enables input)
15. Session history updated with user + assistant messages

═══════════════════════════════════════════════════════════════════════

KEY DESIGN PRINCIPLES:

✅ Pure CPU Inference (no cloud, no GPU)
✅ No External APIs (no RAG, tools, or function calling)
✅ Streaming UX (word-by-word, not batch)
✅ Session Isolation (UUID per user, thread-safe)
✅ Domain Boundaries (no fabricated order/inventory access)
✅ Graceful Failures (health checks, reconnection, error handling)
